## 拷入

将本包内 `server/` 目录按相同路径复制进项目（本暂存目录届时已位于项目根）。只复制后端实现与随行测试，不包含前端文件。

- 已移除上游通用 key 请求头及服务端密钥环境变量回退；不会读取或保存密钥。冒烟命令中的 `sample.wav` 与密钥由合入方在本机提供，不属于模块产物。

## 缝合（共 2 处，全部单行插入）

1. `server/src/index.ts` 的路由 import 区，新增一行：

   ```ts
   import asrRouter from './routes/system/asr';
   ```

2. `server/src/index.ts` 的 `proxyFallback` 之前，新增一行：

   ```ts
   app.use('/api/asr', asrRouter);
   ```

无新增 npm / Python 依赖，无需修改 `package.json` 或 `pyproject.toml`。

## 契约文档补丁（合入时照抄以下文字追加，含 ⏳ 标记）

- 《新前端对接契约.md》B.2 接口面追加：`POST /api/asr/transcribe`：原始音频转写，支持 OpenAI 兼容 transcriptions 与小米 MiMo chat-audio；密钥分别仅取 `X-OpenAI-Key`、`X-MiMo-Key` 请求头。
- B.5 错误码追加：`BAD_BODY` (400) 缺少音频字节；`NO_KEY` (400) 缺少对应 provider 密钥头；`UNSUPPORTED_FORMAT` (400) 音频格式不受支持；`ASR_UNAUTHORIZED` (401) 上游鉴权失败；`TOO_LARGE` (413) 超过 25 MB；`ASR_UPSTREAM` / `ASR_BAD_RESPONSE` (502) 上游调用或响应异常。
- B.7 上述 `asr` 相关条目后统一标注：`⏳ 前端未接入`

## 验证（合入方执行）

在项目根运行定向测试：

```bash
cd server && npx vitest run --maxWorkers=2 src/__tests__/asr.test.ts
```

运行完整后端检查：

```bash
cd server && npx tsc --noEmit && npx vitest run --maxWorkers=2
```

启动网关后，在另一终端冒烟：

```bash
node scripts/dev.mjs --no-open
curl -X POST http://localhost:8002/api/asr/transcribe -H "Content-Type: audio/wav" -H "X-MiMo-Key: $MIMO_KEY" -H "X-ASR-Style: chat-audio" --data-binary @sample.wav
```

暂存验证结果：模块定向测试通过；TypeScript 全量检查通过。完整 Vitest 为 155 个文件通过、2 个文件失败，1080 个测试通过、3 个失败；失败均在既有群聊测试与后续策略路由之间，非本模块测试，具体文件与处置见 `ledger.md`。
