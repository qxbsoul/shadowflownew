# 模块 ops 接入步骤

来源：上游 a25159a452b5c0e956ae630664774e0ce2847845（PR #46） ｜ 抽取日期：2026-11-07 ｜ 静态校验：通过（import 闭包与禁物扫描、TypeScript `--noEmit`、模块定向测试；完整套件另有 3 个上游群聊断言失败，详见 `ledger.md`）

## 拷入

将本包内 `server/` 目录按相同路径复制进项目（本暂存目录届时已位于项目根）。只复制后端实现与随行测试，不包含前端文件。

- 为保持单包自洽，本包同时带有 `storage/social-publish.ts` 与 `lib/social-platforms/`；这些重叠文件与 `social-publish` 模块逐字节一致，两包同时合入时保留一份即可。

## 缝合（共 2 处，全部单行插入）

1. `server/src/index.ts` 的路由 import 区，新增一行：

   ```ts
   import opsRouter from './routes/ops/ops';
   ```

2. `server/src/index.ts` 的 `proxyFallback` 之前，新增一行：

   ```ts
   app.use('/api/ops', opsRouter);
   ```

无新增 npm / Python 依赖，无需修改 `package.json` 或 `pyproject.toml`。

## 契约文档补丁（合入时照抄以下文字追加，含 ⏳ 标记）

- 《新前端对接契约.md》B.2 接口面追加：`/api/ops`：代运营概览、一键多平台营销分发、快递承运商与运单履约/轨迹。
- B.5 错误码追加：`INVALID_PRODUCT_ID` (400) 商品 ID 为空；`PRODUCT_NOT_FOUND` (404) 商品不存在；`INVALID_TARGETS` (400) 分发目标无效；`ACCOUNT_NOT_FOUND` (400) 指定社交账号不存在；`NO_ACCOUNT` (400) 目标平台无可用账号；`SHIPMENT_NOT_FOUND` (404) 运单不存在；`INTERNAL` (500) 代运营内部错误。
- B.7 上述 `ops` 相关条目后统一标注：`⏳ 前端未接入`

## 验证（合入方执行）

在项目根运行定向测试：

```bash
cd server && npx vitest run --maxWorkers=2 src/__tests__/ops-flow.test.ts
```

运行完整后端检查：

```bash
cd server && npx tsc --noEmit && npx vitest run --maxWorkers=2
```

启动网关后，在另一终端冒烟：

```bash
node scripts/dev.mjs --no-open
curl http://localhost:8002/api/ops/overview
```
