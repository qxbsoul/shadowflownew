# ShadowFlow 本地启动指南

这份指南对应当前已经联调好的 `D:\shadowflow` 工作区。正常情况下，只需要在根目录执行 `npm run dev`，不需要分别打开三个终端。

## 1. 服务关系与访问地址

```text
浏览器 → React :3007 → /api/** → Node 网关 :8002 → Python FastAPI :8000
```

| 项目 | 地址 | 用途 |
| --- | --- | --- |
| 工作台 | http://localhost:3007 | 日常使用的唯一页面 |
| Node 健康检查 | http://localhost:8002/health | 判断网关进程是否存活 |
| 全链路业务检查 | http://localhost:8002/api/opc/companies | 判断网关到 Python 是否连通 |
| Python 接口文档 | http://localhost:8000/docs | 调试后端接口 |

前端不会直接请求 `:8000`。另外，网关健康检查是 `/health`，**不是** `/api/health`。

## 2. 环境要求

- Windows 当前工作区已便携配置 **Node 22.16.0 + npm 10.9.2**，位于 `D:\shadowflow\.tools\node22`。
- Python **3.10 或更高版本**；本次验证使用 Python 3.12。
- 可用端口：`3007`、`8002`、`8000`。
- 如果 `.tools\node22` 被移走，需要自行安装 Node 22。网关的 `better-sqlite3` 不能混用其他 Node 大版本安装出的原生模块。

可先检查：

```powershell
python --version
D:\shadowflow\.tools\node22\node.exe --version
```

## 3. 首次安装依赖

已经安装过依赖并且 `node_modules` 存在时，可直接跳到第 4 节。

### 3.1 安装 Python 后端

```powershell
cd D:\shadowflow\ShadowFlow-backend
python -m pip install -e ".[server]"
```

`.[server]` 已足够运行服务；只有需要跑完整 Python 开发测试时才需要 `.[server,dev]`。

如果希望固定使用某个 Python 解释器，可在启动前设置：

```powershell
$env:SF_PYTHON = "D:\path\to\python.exe"
```

启动器按 `SF_PYTHON` → `ShadowFlow-backend\.venv` → 系统 `python` 的顺序选择解释器。

### 3.2 安装网关与前端依赖

使用工作区自带的 Node 22：

```powershell
cd D:\shadowflow
.\.tools\node22\npm.cmd --prefix .\ShadowFlow-backend\server ci
.\.tools\node22\npm.cmd --prefix .\shadowflow-react ci
```

如果使用自己安装的 Node 22，上述两条可分别进入对应目录执行 `npm ci`。网关依赖请务必用 Node 22 安装，不要先用 Node 24 安装后又用 Node 22 启动。

## 4. 日常一键启动

打开一个 PowerShell 或终端：

```powershell
cd D:\shadowflow
npm run dev
```

启动器会自动：

1. 选择便携 Node 22；
2. 探测 `:8000`：如果没有服务就启动 Python；如果已经是 ShadowFlow，就打印“自动复用”并跳过重复启动；
3. 拉起 Node 网关 `:8002` 和 React `:3007`；
4. 等待服务就绪并调用 `/api/opc/seed` 初始化演示公司；重复初始化不会要求手工建公司。

看到“全部服务已就绪”后，打开 **http://localhost:3007**。左下角显示 **“Gateway 已连接 · 实时数据”** 即启动成功。

停止时回到这个终端按 **Ctrl+C**，启动器会清理本次拉起的进程；自动复用的原有 Python 会继续运行。不要直接保留多个重复网关或前端实例。

### 显式跳过 Python 启动

自动复用通常不需要额外参数。如果希望明确只启动网关和前端，也可执行：

```powershell
cd D:\shadowflow
npm run dev -- --no-python
```

`--no-python` 只是“不重复启动 Python”，不是离线模式；网关仍会代理到现有 `:8000`。如果 `:8000` 上没有 ShadowFlow，业务接口会返回 503，此时不要使用该参数。

## 5. 可选：三个终端手动启动

适合分别查看日志或只调试其中一层。以下命令使用工作区便携 Node 22。

### 终端一：Python FastAPI

```powershell
cd D:\shadowflow\ShadowFlow-backend
python -m uvicorn shadowflow.server:app --host 127.0.0.1 --port 8000 --reload
```

### 终端二：Node 网关

```powershell
cd D:\shadowflow\ShadowFlow-backend\server
D:\shadowflow\.tools\node22\node.exe node_modules\tsx\dist\cli.mjs watch src/index.ts
```

### 终端三：React 前端

```powershell
cd D:\shadowflow\shadowflow-react
D:\shadowflow\.tools\node22\node.exe node_modules\vite\bin\vite.js --host 0.0.0.0 --port 3007 --strictPort
```

前端启动时会自动初始化演示公司。需要手工初始化或重置检查时可执行：

```powershell
curl.exe -X POST http://localhost:8002/api/opc/seed
```

手动模式需要分别关闭三个终端的服务。

## 6. 启动后自检

按以下顺序检查：

```powershell
curl.exe http://localhost:8000/
curl.exe http://localhost:8002/health
curl.exe http://localhost:8002/api/opc/companies
```

预期：

1. Python 根路径有 HTTP 响应；
2. 网关 `/health` 返回健康信息；
3. 公司接口返回 `items`，其中能看到演示公司；
4. 前端左下角为“Gateway 已连接 · 实时数据”，而不是“演示数据”。

再进行一次小范围业务检查：

1. 在“工作台”输入一条派工需求，确认出现真实项目和任务步骤；刷新页面，确认当前公司的对话和项目卡片仍能恢复；
2. 项目进入审批后打开“人工审批”，先填写意见并驳回，确认任务返工且出现新待审批，再逐步批准至交付；
3. 在“交付成果”打开项目预览，确认全部任务记录按顺序显示、等待数秒不闪烁；当前 `[simulated]` 内容只表示后端模拟执行记录。若是本次自检项目，可点击“删除项目”并确认卡片消失；
4. 在“定时任务”创建每天 09:00 的任务，确认显示“每天 09:00”，再暂停和删除；
5. 打开组织架构、数据看板和知识库，确认没有接口报错。

## 7. 模型、BYOK 与当前模拟执行

当前 OPC 执行器的真实模型 Provider 对接尚未完成：`_llm_complete()` 引用了 `shadowflow.llm` 中不存在的 `completion`，会进入既有模拟降级分支。因此带 `[simulated]` 标记的输出只表示项目流程和任务状态已推进，**不代表模型实际生成、检索或制作了业务成果**。审批区看到这些记录时，也没有真实模型成果可供核验。

前端仍保留通用 BYOK 配置能力。例如在浏览器开发者工具 Console 中设置 DeepSeek：

```js
localStorage.setItem('sf_default_provider', 'deepseek');
localStorage.setItem('sf_deepseek_key', '填入你自己的 key');
location.reload();
```

key 只保存在当前浏览器，请求时仅发送 `X-Deepseek-Key`，不会把其他 provider 的 key 一起发送。前端尚未新增独立密钥设置页面。清除方式：

```js
localStorage.removeItem('sf_deepseek_key');
```

**仅配置 BYOK 不会让当前 OPC 自动变成真实执行。** 需要先明确后端 Provider 适配与执行器接入方案，本次没有擅自修改这部分。

## 8. 当前功能边界

| 能力 | 当前状态 |
| --- | --- |
| 老板派工、项目拆解和状态推进 | 已接真实内部项目 API，不走支付订单；任务输出目前为 `[simulated]` 模拟记录 |
| 刷新后恢复对话 | 当前浏览器本地过渡实现，在线按公司、离线分别隔离，最多 200 条；后续可替换为聊天后端 |
| 人工审批、驳回返工、批准后继续 | 已接真实 API；支持待审批／已批准／已驳回／全部筛选；模拟输出会明确提示 |
| 项目进度、交付列表和任务记录预览 | 已接真实项目数据；按顺序展示全部任务输出，终态预览不随轮询闪烁 |
| 内部项目删除 | 已在交付预览中接入；级联删除任务、审批和关联台账，删除前需确认 |
| 失败任务重试 | 已在失败项目预览中接入；只重置失败任务，不重复已完成任务 |
| 部门/花名册读取、创建部门、入职和移除 | 已接真实 API |
| 定时任务创建、启停、删除 | 已接真实 API |
| 用量看板、公司盈亏、知识包列表 | 已接真实 API |
| 商品／订单／支付、订单事件与取消、单任务读取与强制执行、收入登记 | 后端有接口，当前工作台无页面；订单项目不能直接删除 |
| 知识包创建／重建索引／详情、定时任务运行历史、通用会话／团队／运行平台 | 后端有接口，当前工作台无页面 |
| 部门重命名/删除、独立岗位增删改、员工资料和汇报关系编辑 | 前端有入口，后端缺对应写接口；操作会明确提示，不伪造成功 |
| 知识包查询、附件上传、PDF 导出、通用错误“重试” | 后续扩展项，当前没有伪造成功 |
| `/workflow/*` SSE | 本轮未使用，保留原后端前缀限制 |

早期联调验收产生的 4 条“联调验收”项目已定向清理，不再显示。后续验收项目可直接在“交付成果”中打开预览并选择“删除项目”，不要直接改数据库。

## 9. 稳定备份与回滚

本轮核心流程修改前的稳定版本位于：

```text
D:\shadowflow\backups\stable-20261107-1228
```

备份包含前后端源码、配置和 5 个 SQLite 在线一致性快照，不包含依赖目录。需要回滚时：

1. 先停止所有 ShadowFlow 服务，确认 `3007`、`8000`、`8002` 不再监听；
2. 备份回滚前仍需保留的新数据；
3. 在根目录执行：

```powershell
cd D:\shadowflow
powershell -ExecutionPolicy Bypass -File .\rollback-stable.ps1
```

4. 看到恢复成功提示后重新启动：

```powershell
npm run dev
```

回滚会覆盖本轮新代码以及备份之后产生的数据库内容，不是“只撤销某一个文件”。脚本会保留 `node_modules`、`.venv` 和便携 Node，无需重新安装依赖。

## 10. 常见问题

### 提示 Node 22 / better-sqlite3 版本错误

一键启动会优先选择 `.tools\node22`。若重新安装过网关依赖，用便携 Node 22 重装：

```powershell
cd D:\shadowflow
.\.tools\node22\npm.cmd --prefix .\ShadowFlow-backend\server ci
```

不要在 Node 24 下安装原生模块后再用 Node 22 运行。

### 提示端口被占用

检查端口：

```powershell
netstat -ano | findstr :3007
netstat -ano | findstr :8002
netstat -ano | findstr :8000
```

- `:3007` 和 `:8002` 需要先停止旧的 ShadowFlow 前端或网关实例。
- 如果 `:8000` 是已经运行的 ShadowFlow Python，当前启动器会自动复用，无需额外参数；也可显式执行 `npm run dev -- --no-python`。如果是其他程序，请先更换或停止该程序。
- 自动复用不会重载代码。修改 Python 后，应停止旧的 ShadowFlow Python 再执行 `npm run dev`，不要继续复用旧进程。
- 不要随意结束不认识的系统 Python 进程。

### Python 依赖不全

```powershell
cd D:\shadowflow\ShadowFlow-backend
python -m pip install -e ".[server]"
```

如果使用虚拟环境，先激活它，或把 `SF_PYTHON` 指向虚拟环境中的 `python.exe`。

### 页面显示“演示数据”

这表示前端没有连通完整链路。依次检查 `:8000`、`8002/health` 和 `8002/api/opc/companies`，再刷新页面。演示模式只用于离线查看，不会把未成功的在线操作伪装成真实结果。

### 派工后停在人工审批

这是正常的风险闸门，不是白屏或假成功。打开左侧“人工审批”，选择“批准并继续”或“驳回返工”；批准意见可选，驳回意见必填。若后续还有审批节点，项目会继续停在下一节点，全部完成后才显示已交付。

### 项目执行失败或需要删除

打开“交付成果”，点击对应项目卡片。失败项目会显示“重试失败任务”；所有内部项目都有“删除项目”入口。删除不可撤销，商务订单项目需先走订单取消或归档流程。

### 出现 `NO_API_KEY`

当前选择的模型需要 key。按第 7 节配置对应 provider 的 BYOK，或先使用后端支持的模拟输出模式。不要连续重试同一个缺少 key 的请求。

## 11. 修改代码后的检查

在根目录执行：

```powershell
npm run build
npm run check:gateway
```

分别对应 React 类型检查/生产构建和 Node 网关 TypeScript 构建。后端核心测试：

```powershell
cd D:\shadowflow\ShadowFlow-backend
.\.venv\Scripts\python.exe -m pytest tests/api/test_opc_os.py -q
```

前端新增请求时，应扩展 `shadowflow-react/src/api.ts` 和 `store.ts`，不要在组件里另写裸 `fetch`，也不要让页面绕过 Node 网关直连 Python。
