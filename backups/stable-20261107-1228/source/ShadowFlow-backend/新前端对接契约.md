## 附录 B · 新前端对接契约（原样交给写前端的 agent）

> 配合：Figma 设计稿、活的后端（localhost:8000/8002）、`backend-openapi.json`。

### B.1 拓扑

```
React 前端 → dev: vite proxy /api → :8002 ｜ prod: nginx 同域反代 /api → :8002（无 CORS）
Node 网关 :8002（自己处理一批路由）→ 未匹配 /api/\* 自动转发
Python FastAPI :8000（全量业务 API）
```

* 健康检查：`:8002/health`、`:8000/`
* Python 挂时网关返 503 + `PYTHON\_BACKEND\_UNAVAILABLE`，前端显示"后端离线"不要白屏
* 前端只认 `/api/\*\*`，**永不直连 :8000**

### B.2 接口面

* **Python 全量**：以 `backend-openapi.json` 为准，TS 类型用 `npx openapi-typescript backend-openapi.json -o src/api-types.ts` 生成
* **Node 网关**（无 OpenAPI，权威来源 `server/src/index.ts` 的挂载表）：run-sessions、runs、agents、teams（仅 DAG 部分）、skills、design-systems、export、settings、cli（本地 CLI 探测）、clawhub（含 SSE 日志）、acp、artifacts、auth（SIWE+访客）、projects、conversations、memory-entries、memory/lessons、memory/handoff、dashboard、merchant、groups（仅发消息被拦，其余在 Python）、fs（目录浏览）、knowledge-vaults、llm；另有 `/projects/\*` 静态产物预览（iframe sandbox 用）

### B.3 BYOK 契约（安全红线）

14 个 provider 的 key 只存浏览器 localStorage（`sf\_{provider}\_key`），**永不上传服务器存储**；用请求头传递，后端即用即弃；**最小披露——一个请求只发当前选中 provider 的那一个 key**：

anthropic/openai/deepseek/zhipu/mimo/google/qwen/moonshot/mistral/groq/openrouter/ollama/lmstudio/azure，请求头格式 `X-{Provider}-Key`（如 `X-Anthropic-Key`）。默认 provider 存 `sf\_default\_provider`，后端按请求体 `provider` 字段选 header。用 fetch 拦截器统一注入，不要逐请求手写。

### B.4 SSE

运行事件流 `GET /api/workflow/runs/{run\_id}/events` 支持 `Last-Event-ID`（断线重连不丢事件）；ClawHub 安装日志也是 SSE。SSE 客户端统一封装（重连+退避）；vite proxy / nginx 必须关 SSE 缓冲（nginx：`proxy\_buffering off`、`X-Accel-Buffering: no`）。

### B.5 错误约定

统一信封 `{"error":{"code","message","trace\_id"}}`；已知 code：`POLICY\_VIOLATION`(403)、`STATE\_CONFLICT`(409)、`PYTHON\_BACKEND\_UNAVAILABLE`(503)、`RUN\_NOT\_FOUND`(404)、429 限流。**策略驳回是正常业务流程（驳回闭环是产品特性）**，按状态展示，不要当异常弹窗。

### B.6 开发约定

先跑通一条核心链路（鉴权 → 首页 → 一个主页面）再铺其余页面；接口格式以 openapi.json + 本文档为准，**不要脑补**（Figma 只有视觉没有接口）；本地 vite proxy `/api → localhost:8002`，部署 = build 产物 + nginx 同域反代。

### B.7 业务语义补充（依据当前后端契约整理）

* 页面清单与对应接口：
  * 登录／访客：`/api/auth`；鉴权失败不得静默跳转成游客成功态。
  * 首页与用量看板：`/api/dashboard`、`/api/runs`、`/api/run-sessions`。
  * 项目与会话：`/api/projects`、`/api/conversations`、`/api/run-sessions`；产物 iframe 只使用 `/projects/*` 沙箱地址。
  * Agent／Team：`/api/agents`、`/api/teams`、`/api/agents/registry/packs`；Pack 列表以注册表实际内容为准，不在前端写死数量。
  * 工作流运行详情：`/api/runs/*`、`/api/workflow/runs/*`；图、任务树、产物血缘、检查点和事件流按 OpenAPI 字段渲染。
  * Skill 与设计系统：`/api/skills`、`/api/design-systems`、`/api/export`。
  * 审批中心：`/api/groups/{group_id}/approvals/pending`、`/api/approvals/events`、`/api/approvals/{approval_id}/approve|reject`。
  * 记忆与知识：`/api/memory-entries`、`/api/memory/*`、`/api/knowledge`、`/api/knowledge-vaults`。
  * 设置与执行器：`/api/settings`、`/api/cli`、`/api/acp`；未安装的 CLI／ACP 展示安装引导，不显示为执行成功。
  * 群组与商业化：`/api/groups`、`/api/merchant`、`/api/opc`；群消息发送由 Node 网关处理，其余未匹配路由由 Python 处理。
* 驳回闭环的 UX 预期：
  1. 用 pending 列表和 `approval.pending` SSE 展示待处理项，保留审批原因、关联 group／run／gate 上下文。
  2. 批准调用 `approve`；驳回调用 `reject` 并提交 `reason`。请求未成功前不得本地伪造 resolved 状态。
  3. 以 `approval.resolved` 和运行事件流刷新页面；断线按统一 SSE 重连策略恢复，不重复提交审批。
  4. `POLICY_VIOLATION`、`STATE_CONFLICT` 和策略驳回属于可恢复业务状态，展示原因及下一步操作，不使用无上下文的异常弹窗。
* 其他后端约束：
  * 前端只访问 Node :8002 的 `/api/**`，不得把 Python :8000 当成第二个前端入口。
  * 非流式 LLM 请求缺少当前 provider 密钥时返回 HTTP 401 + `NO_API_KEY`；流式请求在 SSE error 帧中返回同一代码并正常发送终止帧。前端应引导补齐当前 provider 的 BYOK，而不是重试轰炸。
  * 本节约束均可由路由、测试或 OpenAPI 验证；新增只有产品侧知道的语义时，由项目负责人继续补充，不能靠前端猜测。
